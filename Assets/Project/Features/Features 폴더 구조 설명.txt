[Features 폴더 구조 설명]

BootStrap

게임 시작과 씬 초기화를 담당한다.
GameRoot, SceneRoot, Context를 둔다.
실제 전투/이동/UI 로직은 넣지 않는다.

Core

모든 기능이 공유하는 공통 기반이다.
Interface, Event, Damage, Resource, Manager를 둔다.
전체에 영향이 크므로 함부로 수정하지 않는다.

Player

플레이어 조작과 상태를 담당한다.
입력, 이동, 파쿠르, 전투 입력, 카메라를 둔다.
무기 세부 구현은 Weapons에서 처리한다.

Weapons

메인 무기와 보조 무기를 담당한다.
메인은 풍/수/화 주술, 보조는 부적/무령 계열로 둔다.
UI와 Quest를 직접 참조하지 않는다.

Execution

처형 시스템을 담당한다.
파살, 흡혼, 처형 가능 판정, 처형 보상을 둔다.
적은 직접 참조하지 않고 인터페이스로 처리한다.

Enemies

몬스터와 보스를 담당한다.
AI, 체력, 피격, 경직, 그로기, 보스 패턴을 둔다.
UI와 Quest를 직접 참조하지 않는다.

Stage

스테이지 장치를 담당한다.
문, 봉인, 제단, 함정, 트리거, 스폰을 둔다.
Player 구체 클래스를 직접 참조하지 않는다.

Quest

퀘스트 진행을 담당한다.
목표 조건, 진행도, 완료 처리, 보상을 둔다.
Enemy, Stage, Player를 직접 참조하지 않고 이벤트를 사용한다.

UI

화면 표시를 담당한다.
체력, 탄약, 무기, 차징, 처형 표시, 퀘스트 가이드를 둔다.
게임 로직을 처리하지 않고 표시만 한다.

Presentation

연출과 피드백을 담당한다.
Animation, VFX, SFX, 카메라 흔들림, 히트스톱을 둔다.
게임 판정을 처리하지 않는다.

[공통 규칙]

Core는 합의 없이 수정하지 않는다.
UI는 Player, Enemy, Weapon을 직접 참조하지 않는다.
Weapon은 UI와 Quest를 직접 참조하지 않는다.
Enemy는 UI와 Quest를 직접 참조하지 않는다.
Stage는 Player 구체 클래스를 직접 참조하지 않는다.
Animation, VFX, SFX는 게임 판정을 처리하지 않는다.
기능 연결은 직접 참조보다 Interface와 Event를 우선 사용한다.
각 기능은 자기 폴더 안에서 개발한다.
씬과 공용 프리팹은 담당자만 수정한다.
기능 개발은 하위 브랜치에서 작업 후 병합한다.
